## Phase 2 — Mock Data Specification (LOCK — DO NOT VARY)

### 2.1 Time window — 2-Shift Continuous Operation

- `mock_window = clamp(InfluxDB range, max=7 days)`
- **โรงงานรัน 7 วัน/สัปดาห์** — ไม่ skip weekend
- **2 shifts ต่อวัน** (timestamps in UTC):

| Shift | Window | Effective production hrs |
|---|---|---:|
| Day shift   | `07:30 – 16:30` | 9 hrs |
| Night shift | `17:30 – 06:30 next day` | 13 hrs |

- **Handover gap:** `16:30–17:30` (1 hr) + `06:30–07:30` (1 hr) — ไม่มี order start ในช่วงนี้
- ทุก timestamp = UTC, type = `TIMESTAMP WITHOUT TIME ZONE`

⚠️ **Implementation note:** night shift คร่อมเที่ยงคืน → ต้อง iterate by shift (ไม่ใช่ by day) เพื่อหลีกเลี่ยง bug ที่ planned_start จาก 23:00 บวก 60 min กลายเป็น 00:00 วันถัดไป

```python
def iter_shifts(start_date, end_date):
    """Yield (shift_start_dt, shift_end_dt, shift_label) tuples."""
    cur = start_date
    while cur <= end_date:
        yield (datetime.combine(cur, time(7, 30)), 
               datetime.combine(cur, time(16, 30)), 'DAY')
        # night shift starts 17:30 today, ends 06:30 next day
        yield (datetime.combine(cur, time(17, 30)),
               datetime.combine(cur + timedelta(days=1), time(6, 30)), 'NIGHT')
        cur += timedelta(days=1)
```

### 2.2 Production order generation

**Per shift** (not per day):
- Day shift: ~7–9 orders (9 hrs ÷ ~75 min/order cycle)
- Night shift: ~10–13 orders (13 hrs ÷ ~75 min/order cycle)
- planned_start: stagger ทุก ~75–90 min ภายใน shift window (15–30 min idle gap ระหว่าง orders)
- planned_end: `planned_start + 60 min`
- **last order ใน shift:** ห้าม `planned_end > shift_end` — ตัดทิ้งถ้าเกิน
- qty_ordered: `random_int(100, 300)`
- model_id: weighted random `{1: 0.4, 2: 0.4, 3: 0.2}`

### 2.3 Production batch generation (per order)

- batch count: `random_int(2, 4)`
- qty_planned split:
  - constrained random where each batch ≥ 30% of avg (`qty_ordered / n_batches`)
  - `sum(batches) = qty_ordered` exactly
- batch duration: `60 / n_batches` minutes (even split → 15, 20, หรือ 30 min)
- inter-batch gap: `random_int(2, 5)` min within order window
- line_id: 1 (only one line)
- **status_code initial: `'CREATED'`**
- **start_time, end_time: `NULL` initially** ← trigger จะ fill ตอน insert events

### 2.4 Yield + qty_out

```python
from numpy.random import beta
import numpy as np

yield_rate = float(np.clip(beta(95, 5), 0.85, 1.00))
qty_out = round(qty_planned * yield_rate)
```

**ห้าม UPDATE qty_out ทีหลัง** — set ใน INSERT batch row เลย

### 2.5 Event log generation per batch

สร้าง events ตามลำดับ chronological:

1. **CREATED** ที่ `planned_start - 5 min`, no reason
2. **STARTED** ที่ `batch.actual_start_time`, no reason
3. (15% chance) **PAUSED** + **RESUMED** middle of batch:
   - PAUSED ที่ random middle, `reason='LUNCH_BREAK'` หรือ `'EQUIPMENT_FAULT'`
   - RESUMED 1–3 min later, no reason
4. **COMPLETED** ที่ `batch.actual_end_time`, no reason

**Insert order matters:**

```python
# 1. Insert batch with status='CREATED', times=NULL
INSERT INTO production_batch (..., status_code, start_time, end_time)
VALUES (..., 'CREATED', NULL, NULL)

# 2. Insert lifecycle events ตามลำดับเวลา → trigger sync อัตโนมัติ
INSERT INTO batch_status_event (batch_id, status_code, reason_code, event_ts) VALUES
  (X, 'CREATED', NULL, planned_start - INTERVAL '5 min'),
  (X, 'STARTED', NULL, actual_start_time),
  (X, 'COMPLETED', NULL, actual_end_time)
```

⚠️ **DO NOT** manually UPDATE `production_batch.status_code/start_time/end_time` — trigger จัดการ

⚠️ **Microsecond precision required:** `event_ts` ต้องไม่ซ้ำใน batch เดียว (UNIQUE constraint `uq_batch_event_ts`) → ใช้ `datetime + timedelta(microseconds=...)` ถ้าจำเป็น

### 2.6 QC record (1:1 batch, ทุก COMPLETED batch)

```python
qty_inspected = max(1, round(qty_out * 0.05))
qty_failed = numpy.random.binomial(qty_inspected, p=0.03)
qty_passed = qty_inspected - qty_failed
inspected_at = batch.end_time + timedelta(minutes=uniform(2, 8))
```

### 2.7 QC defect (M:N junction)

ถ้า `qty_failed > 0`:
- random choose 1–3 defect codes จาก **leaf nodes** (`category='LEAF'`) ของ defect_type
- qty_affected: split qty_failed across chosen defects (sum = qty_failed, each ≥ 1)
- notes: empty หรือ generic message

⚠️ **FK leaf-only:** `qc_defect.defect_code` ใช้เฉพาะ leaf (15 codes) — ห้ามใช้ parent codes (TERMINAL, COVER, WELDING, PLATE, CASING)

### 2.8 Downtime events

**Per day** (covering both shifts):
- 2–3 unplanned events random ใน production hours (day or night shift)
  - weighted: `EQUIPMENT_FAULT`, `SENSOR_ALARM`, `POWER_OUTAGE`
- 0–1 `PLANNED_PM` event ใน handover gap (16:30–17:30 หรือ 06:30–07:30)
  - batch_id = NULL (ไม่มี batch รันตอน handover)
- machine_id: random `{1, 2, 3}`
- duration: `random_int(5, 30)` min
- end_ts = start_ts + duration
- batch_id:
  - ถ้า downtime overlap กับ active batch → set `batch_id` of that batch
  - ถ้า PLANNED_PM ใน handover gap → `batch_id = NULL`
- **ห้าม set `duration_min`** — trigger `fn_compute_downtime_duration` จะ compute เอง

⚠️ **Reason code category match:**
- `batch_status_event.reason_code` → category `'BATCH_HOLD'` หรือ `'BATCH_ABORT'`
- `downtime_event.reason_code` → category `'MACHINE_DOWNTIME'`

⚠️ **DO NOT** manually UPDATE these — trigger จัดการเอง:

| Column | Trigger |
|---|---|
| `production_batch.status_code` | `trg_sync_batch_status` |

⚠️ **Insert pattern ที่ถูกต้อง (ตัวอย่างเต็ม):**

```sql
-- 1. Insert batch as CREATED, times NULL
INSERT INTO production_batch (
    batch_id, order_id, line_id, status_code, qty_planned, qty_out, 
    start_time, end_time
) VALUES (
    101, 50, 1, 'CREATED', 75, 72, 
    NULL, NULL
);

-- 2. Insert lifecycle events — trigger จัดการ sync
INSERT INTO batch_status_event (batch_id, status_code, reason_code, event_ts) VALUES
    (101, 'CREATED',   NULL,              '2026-04-18 08:55:00'),
    (101, 'STARTED',   NULL,              '2026-04-18 09:00:00'),
    (101, 'COMPLETED', NULL,              '2026-04-18 09:30:00');

-- หลัง events insert เสร็จ trigger ทำให้ production_batch กลายเป็น:
--   status_code = 'COMPLETED'
--   start_time  = '2026-04-18 09:00:00'
--   end_time    = '2026-04-18 09:30:00'
```

⚠️ **Microsecond uniqueness:**

```python
# ถ้า events ในกลุ่มเดียวกันต้องเรียงลำดับเวลาใกล้ๆ กัน ใช้ microseconds offset
event_ts_1 = base_ts + timedelta(microseconds=0)
event_ts_2 = base_ts + timedelta(microseconds=1)
```

⚠️ **Active batch detection สำหรับ downtime:**

```python
# downtime overlap กับ active batch หรือไม่
def find_active_batch_at(ts):
    return cur.execute("""
        SELECT batch_id FROM production_batch
        WHERE start_time <= %s AND (end_time IS NULL OR end_time >= %s)
          AND status_code IN ('STARTED','PAUSED','RESUMED')
        LIMIT 1
    """, (ts, ts)).fetchone()
```
