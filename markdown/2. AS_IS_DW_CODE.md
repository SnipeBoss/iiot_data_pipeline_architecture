## 1. Executive Summary

| Component | Technology | Hosting |
|---|---|---|
| OLTP | PostgreSQL (Supabase, cloud) | `db.<ref>.supabase.co:5432` |
| Time-series | InfluxDB 2.x (AWS) | `INFLUX_URL` env |
| **Data Warehouse** | **Oracle 10.2.0.3** (`AI03` schema) | `161.246.35.92:1521/orcl` (KMITL) |
| Pipeline | Apache Airflow 2.8 | docker-compose, host-side |
| Bridge | FastAPI on uvicorn (port 8000) | host-side (ไม่ใช่ใน container) |
| API → Oracle | JDBC thin (jaydebeapi + ojdbc8.jar + jpype) | localhost JVM |

**Why so many moving parts:**

1. **Oracle 10g** เก่ากว่าที่ `python-oracledb` thin-mode รองรับ (ต้อง 12c+) — บังคับใช้ JDBC
2. **JDBC ต้องใช้ JVM** — ไม่อยาก bundle Java + jar ใน Airflow container ทุกตัว
3. **FastAPI service** ห่อ JDBC เป็น HTTP API → DAG ใช้ `requests` ตรง ๆ ไม่ต้อง deal กับ JVM
4. **Airflow ใน Docker, FastAPI บน host** — DAG เรียก `host.docker.internal:8000`

**Layering:**
- Kimball star schema 3 ชั้น: **STG → DIM → FACT**
- Merge-by-key (ไม่ใช่ merge-by-date) ที่ระดับ stored procedure → idempotent บน 15-min window

### 3.2 STG (Staging) Layer

**Design rules:**
- **No FK, no surrogate key** — เก็บ business key ตรงจาก source
- **Lineage cols เสมอ:** `src_system`, `pipeline_run_id`, `loaded_at` — debug pipeline ผิด
- **Truncate-and-load** — DAG ส่ง `truncate=True` ทุกครั้ง; STG = buffer ของ 15-min window ล่าสุด ไม่สะสม

#### `STG_PRODUCTION_BATCH` — [01_schema.sql:149-161](../db_module/db_sources/oracle_sql_query/query/01_schema.sql#L149-L161) + [08_alter_stg_production_batch.sql](../db_module/db_sources/oracle_sql_query/query/08_alter_stg_production_batch.sql)

```sql
-- ALTER 2026-04-19 (08_alter):

```

ALTER 2026-04-19 เพิ่ม 4 column เพื่อ carry planning data จาก `production_order` ไปให้ SP คำนวณ batch-level slippage

#### `STG_QC_RECORD` — [01_schema.sql:167-178](../db_module/db_sources/oracle_sql_query/query/01_schema.sql#L167-L178)


#### `STG_SENSOR_AGG` — [01_schema.sql:185-198](../db_module/db_sources/oracle_sql_query/query/01_schema.sql#L185-L198)


**สำคัญ:** `machine_name` และ `metric_name` **ต้องตรงกับ tag/field ใน InfluxDB เป๊ะ** เพราะ SP ใช้ `JOIN ON dm.machine_name = stg.machine_name` แปลงเป็น surrogate key — ผิด 1 ตัวอักษรก็ FACT_SENSOR ว่าง

### 3.3 DIM (Dimension) Layer

**Design rules:**
- **Surrogate key (sequence)** เป็น PK; source key เก็บใน `*_src_id` เผื่อ reverse-lookup
- **SCD Type 1** (overwrite) — POC ไม่ track history
- **Denormalize ได้** เช่น `DIM_MACHINE.line_name` copy มาจาก `production_line` → reporting query ไม่ต้อง JOIN เพิ่ม
- **DELETE + INSERT** ตอน sync (ไม่ใช่ MERGE) — เพราะ FACT ใช้ `*_src_id` lookup ไม่ใช่ surrogate

#### `DIM_DATE` — surrogate key = YYYYMMDD (ไม่ใช่ sequence)

```sql
date_id NUMBER PK,            -- 20260418 ≡ 2026-04-18
full_date DATE,
day_of_week NUMBER(1),        -- 1=Mon..7=Sun (ISO-8601, locale independent)
week_number, month_number, quarter, year
```

`day_of_week` ใช้ ISO anchoring `(TRUNC(d) - TRUNC(d, 'IW')) + 1` แทน `TO_CHAR(d, 'D')` เพราะตัวหลังขึ้นกับ `NLS_TERRITORY` ของ session

#### `DIM_LINE` (NEW 2026-04-19) — [06_dim_line.sql](../db_module/db_sources/oracle_sql_query/query/06_dim_line.sql)

```sql
line_id NUMBER PK,            -- surrogate (SEQ_DIM_LINE)
line_src_id NUMBER,           -- Supabase production_line.line_id
line_name VARCHAR2(50),
area VARCHAR2(50)
```

**Why added:** เดิม OLTP เก็บ `line_id` ที่ `production_order` → ย้ายลงไปที่ `production_batch` (operator เลือก line ตอน execute ไม่ใช่ตอน plan) → DW ต้องแยก DIM_LINE และ FACT_PRODUCTION ต้องเพิ่ม FK `line_id`

#### `DIM_MACHINE`

```sql
machine_id NUMBER PK,          -- surrogate (SEQ_DIM_MACHINE)
machine_src_id NUMBER,         -- Supabase machine.machine_id
machine_name VARCHAR2(10),     -- "M01"/"M02"/"M03" — ตรงกับ InfluxDB tag เป๊ะๆ
line_name VARCHAR2(50)         -- denormalized จาก production_line.name
```

#### `DIM_PRODUCT` ⚠

```sql
product_id NUMBER PK,          -- surrogate
product_src_id NUMBER,
product_name VARCHAR2(100)
```

⚠ **STALE:** OLTP recreate (commit `bcbcbd4` → ปัจจุบัน) ลบ table `product` แล้ว เปลี่ยนเป็น `battery_model` — ดู §11

#### `DIM_METRIC` — seeded inline ใน DDL

```sql
metric_id NUMBER PK,           -- ใส่ค่า explicit (ไม่ใช้ sequence)
metric_name VARCHAR2(50),      -- ตรงกับ field ใน InfluxDB
unit VARCHAR2(20),
machine_name VARCHAR2(10),     -- NULL = ทุกเครื่อง
description VARCHAR2(200)
```

| metric_id | metric_name | unit | machine_name |

| 1 | temperature_c | celsius | M01 |

### 3.4 FACT Layer

**Design rules:**
- **Grain ชัดเจน** — 1 row = 1 measurable event
- **FK ชี้ DIM** ทุก `*_id` (ยกเว้น degenerate dim ที่ลงท้าย `_src_id`)
- **Additive measures** — qty/duration/yield SUM/AVG ได้
- **Precomputed % เก็บไว้** เช่น `defect_rate_pct`, `yield_rate` — แต่ห้ามเฉลี่ย % ตอน aggregate (ต้อง re-derive จาก measure ดิบ)
- **Degenerate dim** = business key ที่ไม่คุ้มสร้าง DIM แยก เก็บใน FACT ตรง ๆ (เช่น `batch_src_id`, `order_src_id`)

#### `FACT_PRODUCTION` — grain = 1 batch

[01_schema.sql:84-100](../db_module/db_sources/oracle_sql_query/query/01_schema.sql#L84-L100) + [07_alter_fact_production.sql](../db_module/db_sources/oracle_sql_query/query/07_alter_fact_production.sql)

```sql
prod_id              NUMBER PK,         -- SEQ_FACT_PRODUCTION
date_id              FK → DIM_DATE,     -- คำนวณจาก end_time
product_id           FK → DIM_PRODUCT,  ⚠ stale
batch_src_id         NUMBER,             -- degenerate dim (Supabase batch_id)
order_src_id         NUMBER,             -- degenerate dim
qty_planned, qty_out NUMBER,
yield_rate           NUMBER(5,4),        -- SP คำนวณ qty_out/qty_planned
start_time, end_time TIMESTAMP,
duration_min         NUMBER(8,2),        -- SP คำนวณ
loaded_at            TIMESTAMP DEFAULT SYSDATE,
-- ALTER 2026-04-19 (07_alter):
line_id              FK → DIM_LINE,
order_planned_start, order_planned_end TIMESTAMP,    -- copy จาก STG
batch_planned_start, batch_planned_end TIMESTAMP,    -- DERIVED: FIFO split
order_est_duration_min,                              -- order_planned_end - order_planned_start
batch_est_duration_min,                              -- batch share × order duration
slippage_min                                         -- actual - batch_est
```

**ไม่มี `machine_id`** — 1 batch ไหลผ่านทั้ง 3 เครื่อง M01→M02→M03; ดู per-machine ต้อง JOIN `FACT_SENSOR` ตาม time overlap

#### `FACT_QUALITY` — grain = 1 QC record (1:1 กับ batch)

[01_schema.sql:106-119](../db_module/db_sources/oracle_sql_query/query/01_schema.sql#L106-L119)

```sql
quality_id       NUMBER PK,
date_id          FK → DIM_DATE,
batch_src_id     NUMBER,           -- degenerate dim
qty_sampled, qty_passed, qty_failed NUMBER,
defect_rate_pct  NUMBER(5,2),      -- SP: qty_failed/qty_sampled*100
inspected_at     TIMESTAMP,
loaded_at        TIMESTAMP DEFAULT SYSDATE
```

ไม่มี `machine_id` เพราะ QC = end-of-line ไม่ผูกกับเครื่องไหนเครื่องเดียว

#### `FACT_SENSOR` — grain = 1 (machine × metric × 15-min window)

[01_schema.sql:127-141](../db_module/db_sources/oracle_sql_query/query/01_schema.sql#L127-L141)

```sql
sensor_id    NUMBER PK,
date_id      FK → DIM_DATE,        -- คำนวณจาก window_start
machine_id   FK → DIM_MACHINE,
metric_id    FK → DIM_METRIC,
window_start, window_end TIMESTAMP,
avg_value    NUMBER(12,4),
min_value, max_value NUMBER(12,4),
sample_count NUMBER(6),             -- ~900 จาก 1Hz × 15min; flag sensor down
loaded_at    TIMESTAMP DEFAULT SYSDATE
```

## 4. Stored Procedures + View

### 4.1 SP_LOAD_DIM_DATE — [02_procedure_dim_date.sql](../db_module/db_sources/oracle_sql_query/query/02_procedure_dim_date.sql)

```sql
PROCEDURE SP_LOAD_DIM_DATE(p_start IN DATE, p_days IN NUMBER)
```

- **Idempotent:** `MERGE INTO DIM_DATE` `WHEN NOT MATCHED THEN INSERT` — รันซ้ำ window ทับกันเป็น no-op
- **Locale-safe:** ใช้ ISO-week anchoring `(TRUNC(d) - TRUNC(d, 'IW')) + 1` แทน `TO_CHAR(d, 'D')`
- **Manual call:** seed 1 ปีตอน bootstrap → `BEGIN SP_LOAD_DIM_DATE(DATE '2026-01-01', 365); END;`
- ❌ DAG ไม่ได้เรียก SP นี้ — ต้องรัน manual ตอน setup

### 4.2 Fact Loaders — [03_procedure_fact_loaders.sql](../db_module/db_sources/oracle_sql_query/query/03_procedure_fact_loaders.sql)

3 procedure ทำ **merge-by-key** (ไม่ใช่ delete-by-date):

#### Why merge-by-key

DAG รันทุก 15 นาที → STG มีแค่ window ล่าสุด ~18 row
ถ้า SP ทำ `DELETE WHERE date_id = :d` จะ **ล้างทั้งวัน** แล้ว rebuild จาก STG window เดียว → FACT เหลือ 18 row ทั้ง ๆ ที่ควรมี 4×18=72 ของ 1 ชั่วโมง

**Fix:** ลบเฉพาะ row ที่ key match กับ STG ปัจจุบัน → idempotent ที่ระดับ key แทน date

#### `SP_LOAD_FACT_PRODUCTION(p_date IN DATE)` — [03_procedure_fact_loaders.sql:27-134](../db_module/db_sources/oracle_sql_query/query/03_procedure_fact_loaders.sql#L27-L134)

- **Delete key:** `batch_src_id IN (SELECT batch_id FROM STG_PRODUCTION_BATCH WHERE end_time IS NOT NULL)`
- **Date derivation:** `TO_NUMBER(TO_CHAR(stg.end_time, 'YYYYMMDD'))` — ไม่ใช้ `p_date` argument (legacy signature)
- **Cross-source lookup:** LEFT JOIN `DIM_PRODUCT ON dp.product_src_id = stg.product_id` ⚠ stale
- **Cross-source lookup:** LEFT JOIN `DIM_LINE ON dl.line_src_id = stg.line_id`
- **Derived columns** (FIFO proportional split):
  ```
  v_order_duration_min = order_planned_end - order_planned_start (in min)
  v_cumulative_qty     = SUM(qty_planned) WHERE order_id matches AND batch_id < current
  v_batch_est_min      = order_duration × (qty_planned / order_total_qty)
  batch_planned_start  = order_planned_start + (cumulative/total) × order_duration
  batch_planned_end    = batch_planned_start + batch_est_min
  slippage_min         = actual_duration - batch_est_min
  ```
- **Cursor FOR-LOOP** + row-by-row INSERT — เพราะ Oracle 10g ห้าม `SEQ.NEXTVAL` ใน `INSERT...SELECT` (ORA-02287)

#### `SP_LOAD_FACT_QUALITY(p_date IN DATE)` — [03_procedure_fact_loaders.sql:140-173](../db_module/db_sources/oracle_sql_query/query/03_procedure_fact_loaders.sql#L140-L173)

- **Delete key:** `batch_src_id IN (SELECT batch_id FROM STG_QC_RECORD)`
- คำนวณ `defect_rate_pct = qty_failed/qty_sampled * 100`
- ⚠ stale: column `qty_sampled` — OLTP ใหม่ใช้ `qty_inspected` (ดู §11)

#### `SP_LOAD_FACT_SENSOR(p_date IN DATE)` — [03_procedure_fact_loaders.sql:179-222](../db_module/db_sources/oracle_sql_query/query/03_procedure_fact_loaders.sql#L179-L222)

- **Delete key:** composite `(machine_id, metric_id, window_start)` — unique ใน scope ของ 15-min window
- **Lookup chain:** STG → DIM_MACHINE (by name) + DIM_METRIC (by name) → FACT
- **Date derivation:** `TO_NUMBER(TO_CHAR(stg.window_start, 'YYYYMMDD'))`
- ทั้ง 3 SP มี `EXCEPTION WHEN OTHERS THEN ROLLBACK; RAISE;` — fail-fast atomicity

### 4.3 V_BATCH_FEATURES — ML view, [09_view_batch_features.sql](../db_module/db_sources/oracle_sql_query/query/09_view_batch_features.sql)

ML feature matrix — JOIN FACT_PRODUCTION + FACT_QUALITY + FACT_SENSOR เป็น 1 row per batch

```sql
SELECT
  -- Categorical (3): product_id, line_id, hour_of_day
  -- Metadata (5): qty_planned, duration_min, batch_est_duration_min,
  --              slippage_min, slippage_ratio
  -- IIoT aggregates (13): per-metric AVG/MAX/STDDEV ของ 6 metrics
  -- Target (2): defect_rate_pct, qty_failed
FROM FACT_PRODUCTION p
JOIN FACT_QUALITY q  ON p.batch_src_id = q.batch_src_id
LEFT JOIN FACT_SENSOR s ON s.window_start < p.end_time
                       AND s.window_end   > p.start_time   -- overlap, not contain
LEFT JOIN DIM_METRIC m  ON s.metric_id = m.metric_id
WHERE q.defect_rate_pct IS NOT NULL
GROUP BY (...)
```

**Time overlap (<, >) ไม่ใช่ containment (>=, <=):** กัน miss window ที่คร่อมขอบ batch (เช่น batch 10:05-10:50 + window 10:00-10:15 → containment ตัดออก, overlap เก็บไว้)

```sql
       b.qty_planned, b.qty_out, b.start_time, b.end_time,
       o.planned_start, o.planned_end,
       (SELECT SUM(qty_planned) FROM production_batch WHERE order_id = b.order_id) AS order_total_qty
  FROM production_batch b
  JOIN production_order o ON b.order_id = o.order_id
 WHERE b.end_time IS NOT NULL
   AND b.end_time >= %s AND b.end_time < %s
```

⚠ stale: `o.product_id` — OLTP ใหม่ใช้ `o.model_id` (ดู §11)

## 10. Critical Design Decisions

### 10.1 Merge-by-key (ไม่ใช่ merge-by-date)

**Problem:** DAG รันทุก 15 นาที → STG มีแค่ window ล่าสุด ~18 row
DELETE WHERE date_id = :d ทำให้ FACT เหลือแค่ 15 นาที ทั้งวันหายหมด

**Solution:** ลบเฉพาะ row ที่ key ตรงกับ STG ปัจจุบัน
- FACT_PRODUCTION: `batch_src_id IN STG`
- FACT_QUALITY: `batch_src_id IN STG`
- FACT_SENSOR: `(machine_id, metric_id, window_start) IN STG`

ผลลัพธ์: idempotent ที่ระดับ key, แต่ทุก rerun ของ window เดียวจะ overwrite row นั้น

### 10.2 STG truncate=True ทุก insert

DAG bulk_insert ส่ง `truncate=True` → server-side TRUNCATE ก่อน executemany INSERT

**Why:** STG = transient buffer ของ window ปัจจุบัน, FACT จะอ่านแล้วลบเอง ดังนั้น STG ไม่ต้องสะสม

### 10.3 FastAPI bridge แทน JDBC ใน Airflow container

ดู §6.1 — แยก JVM/Java ออกจาก Airflow image

### 10.4 InfluxDB tag/field name = lookup key

`STG_SENSOR_AGG.machine_name` = "M01" (string) ต้องตรงกับ:
- `DIM_MACHINE.machine_name` = "M01" (sync จาก Supabase `machine.name`)
- InfluxDB tag `machine_id` = "M01" (NodeRED config)

ผิด 1 ตัวอักษร → JOIN miss → FACT_SENSOR ว่าง

`metric_name` ก็เหมือนกัน — Flux field name ต้องตรงกับ DIM_METRIC.metric_name

### 10.5 Date_id derivation in SP, not in extract

DAG ไม่ส่ง date_id; SP คำนวณเอง `TO_NUMBER(TO_CHAR(end_time/inspected_at/window_start, 'YYYYMMDD'))` — กระจายความรับผิดชอบ: STG รู้แค่ raw timestamp, DIM key เป็นเรื่องของ FACT layer

### 10.6 Time overlap (<, >) สำหรับ batch ↔ sensor JOIN

[Q3 reporting query](../db_module/db_sources/oracle_sql_query/query/04_reporting_queries.sql#L73-L77) + [V_BATCH_FEATURES](../db_module/db_sources/oracle_sql_query/query/09_view_batch_features.sql#L69-L70):

```sql
JOIN FACT_SENSOR fs ON fs.window_start < fp.end_time
                   AND fs.window_end   > fp.start_time
```

**Containment** (`>=, <=`) จะตัด window ที่คร่อมขอบ batch ออก — เช่น batch 10:05-10:50 + window 10:00-10:15 → containment โยนทิ้ง, overlap เก็บไว้

### 10.7 Oracle 10g gotchas (สรุปจาก [README §Oracle 10g Gotchas](../db_module/db_sources/oracle_sql_query/README.md))

1. ไม่มี `GENERATED AS IDENTITY` → ใช้ SEQUENCE
2. `SEQ.NEXTVAL` ห้ามใน `INSERT...SELECT` (ORA-02287) → ต้อง cursor FOR-LOOP
3. `ALTER SEQUENCE ... RESTART` ไม่มี → DROP + CREATE
4. JDBC thin ต้อง `thinLogonCapability=o3`
5. NLS Buddhist calendar default → ALTER SESSION ทุก connection
6. `TO_CHAR(d, 'D')` locale-dependent → ใช้ ISO-week math แทน
7. `DROP IF EXISTS` ไม่มี → wrap ด้วย `BEGIN ... EXCEPTION WHEN OTHERS THEN NULL` (ดู [00_drop_all.sql](../db_module/db_sources/oracle_sql_query/query/00_drop_all.sql))

### 11.3 OLTP เพิ่มหลาย table ที่ DW ยังไม่ได้รองรับ

OLTP ใหม่มี table เพิ่ม (ดู [`01_schema.sql` ของ supabases_sql_query`](../db_module/db_sources/supabases_sql_query/query/01_schema.sql)):

- `batch_status` (lookup) — state machine
- `event_reason` (lookup) — shared reason codes
- `defect_type` (recursive) — defect taxonomy
- `batch_status_event` (event log) — แทน status fields บน batch
- `qc_defect` (M:N junction) — defect-per-QC mapping
- `downtime_event` (event log) — machine downtime
- 2 triggers — `trg_sync_batch_status`, `trg_compute_downtime_duration`

DW ตอนนี้:
- ❌ ไม่มี FACT/DIM สำหรับ defect taxonomy → ไม่มี root-cause analysis
- ❌ ไม่มี FACT_DOWNTIME → OEE ไม่ครบ (Availability ขาด)
- ❌ ไม่มี FACT_BATCH_EVENT → batch lifecycle/timeline ไม่อยู่ใน DW
- ❌ `production_order.model_id` (FK) ยังไม่ map ไปไหน

### 11.4 SP signature `p_date IN DATE` ไม่ได้ใช้

ทั้ง 3 fact loader SP มี parameter `p_date IN DATE` แต่ภายในไม่อ้างอิงเลย — สืบทอดมาจาก legacy version ที่เคยทำ DELETE-by-date

DAG `sp_load_dw` ส่ง `[ds]` ทุกครั้ง (ds = data_interval_start.date()) — ส่งไปก็ทิ้ง

**Recommendation ตอน redesign:** เอา parameter ออก หรือเปลี่ยนใช้เป็น watermark

### 11.5 DIM_DATE seed manual

DIM_DATE ต้อง pre-populate ด้วย `SP_LOAD_DIM_DATE` ก่อน FACT รัน — ถ้าลืม FK จะ fail (date_id ใน FACT ไม่ match DIM_DATE)

ไม่มี DAG/script auto-run — ทำครั้งเดียวตอน bootstrap หรือเมื่อ end of year

### 11.6 ไม่มี `pipeline_run_id` partition / dedup

`STG_*.pipeline_run_id` เก็บไว้ debug แต่ไม่ได้ใช้เป็น key — TRUNCATE ทับทุกครั้งทำให้ lineage หายตอน SP run

ถ้าอยาก audit "row นี้มาจาก DAG run ไหน" หลัง SP rotate → ต้อง add column ลง FACT หรือ append-only STG (ไม่ truncate)

### 11.7 InfluxDB schema assumption

DAG hard-code `measurement="station_1"` — OLTP มี `machine` 3 เครื่อง M01/M02/M03 ใน 1 measurement ผ่าน tag

ถ้า InfluxDB เปลี่ยน measurement (เช่น แยกเป็น `station_m01`, `station_m02`, ...) → DAG ต้องแก้

## Appendix: Things to Carry Forward → New Design

ขอข้อสรุปสั้น ๆ ของสิ่งที่ design ปัจจุบัน "ทำดี" และ "ต้องแก้":

### ✅ ทำดี (carry forward)

1. **3-layer Kimball** (STG/DIM/FACT) — แยกหน้าที่ชัด, debug ง่าย
2. **Surrogate key + `*_src_id`** — DW ไม่ผูกกับ source PK
3. **Merge-by-key** ใน SP — idempotent ที่ระดับ key, รองรับ 15-min cadence
4. **FastAPI bridge** — แยก JVM/JDBC ออกจาก Airflow image
5. **Lineage cols ใน STG** (`pipeline_run_id`, `loaded_at`) — debug-friendly
6. **DIM_DATE.date_id = YYYYMMDD** — readable + portable
7. **Time overlap (<, >) สำหรับ batch ↔ sensor JOIN** — ไม่ miss boundary windows
8. **DIM_METRIC seed inline** — เพิ่ม metric ใหม่ INSERT เดียว ไม่ต้องแตะ schema
9. **NLS_CALENDAR=GREGORIAN per session** — กัน Thai Buddhist calendar bug
10. **ISO-week anchoring** สำหรับ day_of_week — locale-independent

### ⚠ ต้องแก้ใน redesign

1. **Stale `product` references** ทั่วทั้ง chain — ต้อง refactor → `battery_model`
2. **ขาด FACT/DIM** สำหรับ: defect taxonomy, downtime, batch lifecycle events
3. **Legacy `p_date IN DATE` parameter** ที่ SP ไม่ใช้ → ลบหรือ repurpose
4. **`qty_sampled` → `qty_inspected`** rename
5. **DIM_DATE seed manual** — ควรมี DAG/script auto-run
6. **STG truncate-and-load** — สูญ lineage หลัง SP rotate; ควรพิจารณา append + watermark
7. **InfluxDB measurement hard-code "station_1"** — abstract เป็น env หรือ DIM_METRIC source
8. **ไม่มี cross-DAG dependency** ระหว่าง extract → sp_load_dw — ใช้ schedule offset 5 นาทีแทน, fragile
9. **No connection pooling** ใน OracleConnector — ทุก endpoint เปิด connection ใหม่
10. **DIM_PRODUCT/MACHINE sync = full DELETE/INSERT** — ถ้า DIM โต ต่อไปอาจช้า; ควร MERGE
